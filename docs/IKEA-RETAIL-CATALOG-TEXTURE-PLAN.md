## 2. 공식 출처와 이미지 정책

- 각 상품은 `retailer`, `articleNumber`, `productUrl`, `imageSourceUrl`, `checkedAt`, `priceBasis`, `included`, `excluded`를 가진다.
- IKEA CDN은 현재 이미지 응답에 `Access-Control-Allow-Origin`을 제공하지 않아 브라우저 WebGL/Canvas에서 직접 읽을 수 없다.
- 공식 페이지의 `og:image`를 `public/catalog/ikea/`에 저해상도 스냅샷으로 저장하고, JSON에는 원본 URL·로컬 URL·파일 SHA-256을 함께 기록한다.
- UI에는 “IKEA Korea · 가격 확인일”과 공식 상품 링크를 표시한다. 로컬 자산은 이 데모의 시각화 용도이며 재판매·재배포 권리를 주장하지 않는다.
- 네트워크나 이미지 로딩에 실패하면 기존 파라메트릭 색상 재질로 안전하게 폴백한다.

## 3. 데이터·아키텍처 변경

### domain

- `Product`에 구조화된 `retail`과 `appearance` 계약을 추가한다.
- `retail.price`는 KRW 금액, 단위/세트 기준, 포함·불포함, 확인일을 명시한다.
- `appearance`는 로컬 텍스처 URL, 원본 이미지 URL, 투영면(`front | top | curtain | cutout`)과 흰 배경 제거 정책을 가진다.
- 새 실상품 형상 `inductionHob`, `faucet`, `kitchenSink`를 추가한다.

### infrastructure

- IKEA 브랜드 JSON에 12종의 공식 스냅샷 데이터를 저장한다.
- 브랜드 로더가 가격·이미지·투영 필드를 검증하고 기존 `price/priceNote` 비용 계약으로 매핑한다.
- 이미지 파일과 manifest의 URL·SHA-256 대응을 계약 테스트로 고정한다.

### presentation

- `ProductTextureEngine`을 runtime으로 주입한다. 전역 캐시를 사용하지 않고 ref-count cache와 dispose를 관리한다.
- 같은 출처 이미지를 한 번만 로드하고, 흰 배경을 alpha로 변환한 `CanvasTexture`를 생성한다.
- alpha 32 이하의 흰 배경 haze는 crop 경계에서 제외하고, crop된 원본 종횡비를 보존한 채 공식 W/H 또는 W/D envelope 안에 contain-fit한다.
- 기존 파라메트릭 형상은 깊이·측면·그림자를 담당하고 실제 상품 이미지는 front/top/curtain 면에 decal처럼 투영하여 2.5D가 아닌 부피감 있는 3D 결과를 만든다.
- 제품 카드에 공식 이미지, 현재가, 가격 기준, 확인일을 표시한다.

7. REFACTOR — 계약 검사, 레이어 타입검사, 커버리지, 전체 E2E, production preview

## 5. 완료 조건

- 이미지 기반 12종 모두 공식 상품번호·가격·실측·출처·이미지·가격 기준을 가진다.
- 이미지 로딩 성공 시 actual-image texture가 사용되고 실패 시 파라메트릭 재질로 폴백한다.
- 동일 이미지 중복 로드가 없고 texture/canvas 자원이 release된다.
- 실제 3D 캔버스에서 텍스처가 로드됐다는 engine 증거와 비어 있지 않은 시각 결과를 E2E로 확인한다.
- KIVIK를 포함한 front/top/cutout/curtain 투영면이 crop 원본 비율을 바꾸지 않고 공식 envelope를 넘지 않는다.
- `npm run verify`, `npm run test:e2e`, `npm run test:preview`가 통과한다.
