# README 공개 전 비판 검토

최종 검토일: 2026-08-31

## 1차 검토 — 기술 정확성과 근거

### 발견

- `millimetre-accurate`는 데이터 단위를 넘어 변환 정확도까지 보장하는 표현으로 읽힐 수 있었다.
- 영어 설명의 CTA 이름이 실제 한국어 UI와 달라 사용자가 GIF를 따라 하기 어려웠다.
- Node.js 24는 CI 버전이지 실제 최소 실행 조건이라고 입증된 값은 아니었다.
- 정확도 수치와 상업 배포 제한은 근거 문서에 직접 연결되어야 했다.

### 반영

- 표현을 `millimetre-based`로 낮추고 CV 변환을 명시적인 초안으로 제한했다.
- 실제 UI 문자열 `평면도 업로드 → 3D`와 영문 번역을 병기했다.
- 최소 환경을 Node.js 22.19+로 고치고 CI가 Node.js 24임을 분리했다.
- 홀드아웃 수치와 라이선스 판단을 `docs/evidence/` 원문에 연결했다.

## 2차 검토 — 공개 설득력과 재현성

### 발견

- 영어 독자가 한국어 UI GIF에서 어떤 결과를 봐야 하는지 설명이 부족했다.
- GIF 재생성 절차에서 Playwright Chromium 설치 단계가 빠져 있었다.
- GIF의 파일 존재만 확인하면 프레임 병합으로 실제 재생 시간이 짧아지는 문제를 놓칠 수 있었다.
- 기능을 과시하는 문구가 자동 완성으로 오해되지 않도록 실패·보정 경계를 함께 보여야 했다.

### 반영

- 데모 아래에 실제 검출 결과 `벽 25 / 방 6 / 문·창문 7 / 11,800mm`를 영문·국문으로 설명했다.
- `npx playwright install chromium`을 재생성 절차에 추가했다.
- GIF를 `100 frames × 200ms = 20,000ms`, 960×540으로 검증했다.
- 강한 제품 문구 바로 뒤에 축척 게이트, 사용자 보정, production 연구 모델 차단을 명시했다.

## 잔여 한계

- 실제 이사 예정 사용자 3~5명의 관찰 검증은 아직 수행되지 않았다.
- CubiCasa 계열 결과는 연구 근거이며 상업 제품 성능 주장으로 사용할 수 없다.

## 3차 검토 — 코드 드리프트와 정보 구조

### 발견

- 영문 README의 IKEA 상품 수는 12종, 국문은 15종으로 서로 달랐다. 실제 데이터는 15종이며 이 중 로컬 공식 이미지 투영 계약을 가진 항목이 12종이다.
- 아키텍처 도식은 프로젝트 저장을 sessionStorage로만 설명했지만 현재 기본 경로는 URL 워크스페이스별 IndexedDB이고 sessionStorage는 캐시·폴백이다.
- 한샘·리바트 bridge와 설치 의존성 설명이 국문에만 있어 영문 독자가 현재 데이터 경계를 알기 어려웠다.
- README 한 파일에 소개·아키텍처·운영 경계가 밀집되어 목적별 탐색 비용이 컸다.
- 테스트 badge의 280개 수치가 실제 342개와 달랐다.

### 반영

- IKEA 15종과 이미지 투영 12종을 분리해 영문·국문 표현을 일치시켰다.
- IndexedDB, URL workspace, sessionStorage cache/fallback을 도식과 불변식에 반영했다.
- 영문에도 catalog bridge와 support-chain 의존성, 아직 산업 표준으로 입증되지 않았다는 경계를 추가했다.
- `docs/products/`에 개요·아키텍처·워크플로우 HTML 문서를 만들고 README 상단에 목적별 진입 링크를 추가했다.
- 2026-08-31 실제 실행 결과인 Vitest 77 files / 342 tests로 badge를 갱신했다.

## 4차 비판 검토 — 과장, 지속 가능성과 검증 공백

### 발견

- 라이브 URL과 자동 저장이 있으면 클라우드 동기화까지 제공하는 것으로 오해할 수 있다.
- Catalog Protocol 1.0은 유용한 내부 계약이지만 “국내 사이트 대부분” 또는 “업계 표준”이라는 외부 호환성 주장을 입증할 adapter coverage가 아직 없다.
- 자동 테스트와 브라우저 E2E가 많아도 초행 사용자의 이해와 실제 과업 성공을 직접 입증하지는 않는다.
- 고정된 테스트 개수 badge는 다시 드리프트할 수 있다.

### 반영

- 제품 HTML과 README에 로컬 지속성·JSON 보관·계정/기기 동기화 미지원의 차이를 명시했다.
- catalog 설명을 “저장소에서 검증되는 버전형 상호운용 계약”으로 제한하고 광범위 호환성 주장을 보류했다.
- 다음 우선순위를 새 기능이 아니라 3–5명 관찰 세션에서 반복되는 문제의 P0–P3 분류로 고정했다.
- badge는 이번 실행 수치로 수정했지만, 장기적으로는 CI 결과에서 동적으로 생성하거나 개수 표기를 제거하는 편이 안전하다.

## 현재 잔여 한계

- 실제 이사·리모델링 예정 사용자 3~5명의 관찰 검증이 없으므로 사용성·가치 판정은 잠정적이다.
- Project v1 import는 최상위 구조를 검증하지만 모든 중첩 좌표·ID 참조를 schema 수준으로 완전 검증하지 않는다.
- 외부 AI 정상 경로는 사용자의 자격 증명·쿼터·서비스 상태에 의존한다.
- 공개 라이브 URL은 현재 README에 연결했지만 가용성 SLA를 제공하지 않는다.

## 5차 검토 — 언어 분리, 첫 화면과 실제 사용 증거

### 발견

- 영문과 국문을 한 파일에 연속 배치해 기본 README가 지나치게 길고, 한국어 섹션까지 내려가야 언어 전환이 가능했다.
- 제품의 가장 강한 증거인 실제 앱 GIF보다 문서 링크와 긴 기능 열거가 먼저 읽혔다.
- 기존 20초 GIF는 근거 기반 2D 검수 게이트 도입 전 흐름을 사용해 현재 UI에서 더 이상 완주하지 못했다.
- 기존 캡처는 도면 변환과 2D/3D 전환까지만 보여주어 최근 핵심 UX인 상품 배치, 가격 갱신과 워크스루를 증명하지 못했다.
- 테스트 개수 badge는 코드가 바뀔 때마다 수동으로 드리프트했다.

### 반영

- 기본 `README.md`를 영어 전용으로 재구성하고 `README.ko.md`를 새로 만들어 상단 링크로 왕복하게 했다.
- 한 줄 제품 약속 바로 다음에 30초 실제 앱 영상을 배치하고, 기능은 현재 동작 표로 압축했다.
- 캡처가 실제 2D 검수 요소 선택·판정·근거 저장 뒤 3D에 진입하도록 수정했다.
- KIVIK 배치, 가격 갱신, 워크스루·점프를 추가하고 영문 단계 캡션으로 한국어 UI의 의미를 보완했다.
- 테스트 개수 badge를 제거하고 실제 GitHub Actions Verify badge만 상태 근거로 유지했다.

## 6차 검토 — 언어 정직성, 캡처 구성과 유지 가능성

### 발견

- 영어 README가 연결하는 제품 HTML 문서는 현재 한국어 전용이므로 영문 문서로 오해할 수 있었다.
- `Vitest passing` 정적 badge는 Verify badge와 중복되고 실패 상태에서도 초록색으로 남을 수 있었다.
- 첫 30초 결과의 마지막 장면이 워크스루 내부 벽 시점에 오래 머물러 제품 전체 인상이 약했다.
- 가져온 도면에서 고정 canvas 좌표로 상품을 놓으면 방 구조에 따라 배치가 실패해 데모 재생성이 불안정했다.

### 반영

- 영어 README에 HTML 문서가 현재 한국어이며 코드 식별자는 영어로 유지된다고 명시했다.
- 정적 Vitest 상태 badge를 영문·국문에서 모두 제거했다.
- 마지막 장면을 아이소 전체 공간으로 복귀시키고 `Plan it. Place it. Walk it.` 캡션으로 마무리했다.
- 실제 room bounding box 중심 후보를 면적순으로 투영해 유효한 방을 찾도록 캡처를 안정화했다.

### 잔여 한계

- 제품 HTML 문서의 영문판은 아직 없다.
- 30초 GIF는 고정된 한 개 도면의 재현 가능한 제품 데모이며 다양한 도면 스타일의 정확도 근거가 아니다.
- README의 기능 주장은 자동 검증과 코드 근거에 맞췄지만 실제 초행 사용자 3–5명의 관찰 증거는 여전히 없다.
