# 검증 가능한 TDD 작업 규약

## 목적

이 규약은 테스트가 현재 존재한다는 사실과 **테스트를 먼저 실패시키고 구현했다는 사실**을 구분한다. 동작 추가·변경과 버그 수정은 RED → GREEN → REFACTOR의 실행 증거를 남겨야 한다.

테스트 선행을 위해 실패 상태를 기본 브랜치에 커밋할 필요는 없다. 대신 PR 또는 `docs/tdd/` 기록으로 누가 다시 확인해도 이해할 수 있는 최소 증거를 보존한다.

## 적용 범위

다음 작업에는 필수다.

- 사용자에게 보이는 동작의 추가·변경
- 버그 수정과 회귀 방지
- 데이터 변환, 저장, 계산, 검증 규칙 변경
- 성능·호환성·오류 복구 계약 변경

문서, 서식, 주석, 의존성 잠금파일처럼 런타임 계약을 바꾸지 않는 변경은 예외로 할 수 있다. 설정 변경이 빌드·테스트·런타임 동작을 바꾸면 예외가 아니다.

## 필수 사이클

### 1. 계약

구현 전에 관찰 가능한 성공 조건과 실패 조건을 한 문장으로 정한다. 테스트 이름은 구현 함수명이 아니라 그 계약을 설명해야 한다.

### 2. RED

1. 계약을 표현하는 가장 작은 테스트를 먼저 작성한다.
2. 대상 테스트만 실행한다.
3. 테스트가 **의도한 이유로** 실패하는지 확인한다. import 오류, 오타, 잘못된 fixture 실패는 RED 증거가 아니다.
4. 명령, 종료 코드, 핵심 실패 메시지를 기록한다.

기존 코드의 동작을 보존하기 위해 처음 추가한 통과 테스트는 `특성화 테스트`다. 이를 RED로 기록하지 않는다. 버그 수정은 수정 전 코드에서 새 회귀 테스트가 실패해야 한다.

### 3. GREEN

계약을 만족하는 최소 구현을 작성하고 RED와 동일한 명령을 실행한다. 관련 없는 테스트 완화, assertion 삭제, skip 추가, 기준선 하향으로 GREEN을 만들지 않는다.

### 4. REFACTOR

중복과 구조를 정리한 뒤 다음 순서로 검증한다.

1. 대상 테스트
2. `npm run test:contracts`
3. `npm run test:coverage`
4. UI 경로 변경이면 `npm run test:e2e`
5. 번들·렌더 경계 변경이면 `npm run test:preview`
6. 마무리 시 최소 `npm run verify`, 고위험 변경은 `npm run verify:full`

## 테스트 설계 규칙

- 정상 경로와 최소 하나의 경계·실패·복구 경로를 검증한다.
- E2E는 내부 스토어를 준비 용도로 사용할 수 있지만 최종 성공은 가능한 한 화면, 다운로드, 픽셀 또는 사용자 관찰 결과로 단정한다.
- WebGL은 canvas 존재만으로 렌더 성공을 주장하지 않는다. 핵심 시각 결과는 픽셀 또는 스크린샷 근거를 사용한다.
- AI·외부 API는 요청 생성·파싱·오류 매핑을 결정론적으로 단위 테스트하고, 실제 서비스 테스트가 skip되면 사용자 결과는 `미확인`으로 기록한다.
- 벤치마크는 로그만 출력하지 않고 사전 기준선을 assertion으로 갖는다. 기준선을 낮출 때는 원인과 사용자 영향을 증거 기록에 남긴다.
- 테스트 개수, `TDD RED` 주석, 코드와 테스트의 동시 커밋은 RED 증거가 아니다.
- `npm run test:contracts`는 assertion이 전혀 없는 테스트 파일, 커밋된 `.only`, 사실과 다른 `TDD RED` 표식을 차단한다. 개별 assertion의 타당성까지 증명하지는 않으므로 코드 리뷰를 대체하지 않는다.

## 증거 기록

동작 변경 PR은 `docs/tdd/YYYY-MM-DD-<slug>.md`를 추가하거나 PR 본문에 같은 내용을 남긴다.

```markdown
# <변경명>

- 계약: <관찰 가능한 성공/실패 조건>
- 테스트: `<경로:줄>`

## RED

- 명령: `<대상 테스트 명령>`
- 종료 코드: `<0이 아닌 값>`
- 실패 이유: <의도한 계약이 아직 충족되지 않은 이유와 핵심 메시지>

## GREEN

- 명령: `<RED와 동일한 명령>`
- 결과: <통과 개수와 종료 코드 0>

## REFACTOR

- 변경: <구조 개선 또는 없음>
- 전체 검증: `<실행 명령과 결과>`
- 미확인/skip: <없음 또는 판정 영향>
```

민감정보, 전체 로그, 토큰은 기록하지 않는다. 핵심 실패 메시지와 숫자만 남긴다.

## 완료 조건

- 새 동작 또는 수정한 버그를 직접 표현하는 테스트가 있다.
- RED가 의도한 이유로 실패했고 기록되어 있다.
- 동일 테스트가 GREEN에서 통과한다.
- 기존 기준선을 낮추거나 테스트를 건너뛰어 통과시키지 않았다.
- 영향 범위에 맞는 전체 검증이 통과했다.
- 실행하지 못한 외부·시각·사용자 검증을 통과로 쓰지 않았다.
