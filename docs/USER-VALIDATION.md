# 사용자 검증 실행안

## 목표

이사 예정 사용자가 별도 설명 없이 자신의 도면을 3D 배치안으로 만들 수 있는지 확인한다. 기능 선호보다 막히는 지점, 잘못된 결과를 알아차리는지, 수동 보정에 걸리는 시간을 우선 측정한다.

## 참여자와 준비물

- 이사 또는 리모델링 예정 사용자 3~5명
- 참여자 본인의 평면도 이미지와 가로 실측 치수 1개
- 로컬/LAN 실행 앱, 화면 녹화 또는 관찰 메모
- 진행자는 조작법을 먼저 설명하지 않고 막혔을 때만 최소 힌트를 준다.

## 20분 과업

1. 별도 안내 없이 `평면도 업로드 → 3D`를 찾아 본인 도면을 업로드한다.
2. 도면에 적힌 전체 가로 치수를 입력하고 축척 상태와 검출 경고를 설명해 본다.
3. 변환 결과를 적용한 뒤 `2D에서 보정`을 선택한다.
4. 검수 안내에 따라 잘못된 벽·문·방·실측을 찾아 최소 1건 보정한다.
5. `3D 배치`로 전환해 보유하거나 구매 예정인 가구 3개를 실측 크기로 배치한다.
6. 배치안 A/B를 만들고 가격 또는 견적서를 내보낸다.

## 기록할 지표

| 지표                      |              목표 |
| ------------------------- | ----------------: |
| 도면 변환 완료율          |          80% 이상 |
| 업로드 CTA 무힌트 발견률  |          80% 이상 |
| 첫 3D 화면 도달 시간      |          5분 이내 |
| 축척 보정 성공률          |          80% 이상 |
| 잘못된 축척의 조용한 적용 |               0건 |
| 2D 보정 필요성 이해       |          80% 이상 |
| 가구 3개 배치 완료율      |          80% 이상 |
| 진행자 힌트               | 사용자당 2회 이하 |
| 치명 오류·데이터 손실     |               0건 |

CV 품질은 검출 개수보다 사용자가 최종적으로 고친 벽·문·방의 수와 보정 시간을 기록한다. 세션 기록은 `docs/USER-VALIDATION-SESSION-TEMPLATE.md`를 복사해 사용한다.

## 종료 질문

1. 가장 이해하기 어려웠던 단계는 무엇인가?
2. 결과 중 믿기 어려웠던 부분은 무엇인가?
3. 실제 이사 준비에서 다시 사용할 이유와 사용하지 않을 이유는 무엇인가?
4. 다른 사람에게 결과를 보여주려면 어떤 공유 방식이 필요한가?

## 이슈 우선순위

- P0: 데이터 손실, 앱 진행 불가, 잘못된 축척을 알아차릴 수 없음
- P1: 2명 이상이 같은 단계에서 막힘, 핵심 과업 완료에 우회 필요
- P2: 시간 지연이나 반복 작업, 이해 가능한 불편
- P3: 선호·시각 개선

3명 테스트가 끝나면 같은 문제가 2회 이상 나온 항목만 다음 개발 사이클의 상위 과제로 승격한다. 공유 링크와 계정 저장은 종료 질문 결과로 범위를 확정한다.
