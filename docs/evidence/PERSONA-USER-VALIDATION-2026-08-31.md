## 반복 이슈와 우선순위

### P1 — 초기 배치의 방 귀속 저장 누락과 스토어 경계 무검증

- P01과 P02의 독립 세션에서 반복됐다.
- 탑뷰에서 바닥이 보이는 방 내부를 클릭했지만 인스펙터는 모든 제품에 `현재 방 "-"`를 표시했다.
- 후속 코드 감사 결과, 이 표시는 좌표가 실제로 방 밖이라는 증거가 아니라 `addPlacement`가 `roomId`를 저장하지 않은 것이 직접 원인이었다. P01의 좌표가 가로 표기값보다 크다는 사실도 도면 좌표 원점이 0이라는 뜻이 아니므로 범위 밖 증거로 사용할 수 없다.
- 별도의 RED 테스트에서는 스토어 `addPlacement`가 UI 고스트 검사를 우회해 실제 방 밖 좌표와 충돌 좌표를 그대로 추가하는 구조적 결함을 확인했다.
- 후보 조치: 초기 배치에도 이동 확정과 동일한 authoritative room/bounds 검사를 원자적으로 적용하고, 성공 시 확정된 `roomId`를 저장한다.

### P1 — 추정 축척의 2D 검수 약속을 즉시 우회 가능

- P02는 “2D에서 반드시 검수” 체크박스를 선택했지만 적용 완료 화면에서 `바로 3D 보기`를 선택할 수 있었다.
- 후보 조치: 추정 축척일 때는 첫 2D 치수 확인을 완료하기 전까지 바로 3D 경로를 잠그거나, 명시적 재확인과 지속 경고를 요구한다.

### P1 — 저품질 고급 설정 결과가 적용 가능 상태로 승격됨

- P03 기본값은 96벽·0방으로 안전하게 적용이 차단됐다.
- 임계값 180·최소 벽 두께 6px로 바꾸자 50벽·2방·1문이 되어 적용 버튼이 활성화됐다. 실제 도면에는 여러 방이 있어 결과는 명백히 불완전했다.
- 후보 조치: 방 개수 존재 여부만이 아니라 도면 대비 방 커버리지, 폐합률, 비정상 벽 밀도 등 저신뢰 게이트를 추가한다.

### P1 — 2D 보정 화면에서 원본 비교 근거가 사라짐

- P01은 “원본 도면과 비교” 안내를 받았지만 2D 화면에는 변환 벡터만 남고 업로드 원본이 나란히 표시되지 않았다.
- 첫 보정은 진행자 힌트 뒤 문 폭 2,200→900mm를 수정한 것이며, 사용자가 스스로 오류를 식별한 증거가 아니다.
- 후보 조치: 2D 검수 중 원본 오버레이/분할 보기를 유지하고 잘못된 후보를 직접 강조한다.

### P2 — 내부 기술 실패 문구 노출

- 3/3 세션에서 `CNN 실패(unavailable:signal is aborted without reason) → 고전 CV`가 그대로 표시됐다.
- 폴백은 정상 동작했고 콘솔 오류도 없었지만 초보자에게는 제품 오류처럼 보일 수 있다.
- 후보 조치: 사용자에게는 “로컬 모델을 사용할 수 없어 기본 분석으로 처리했습니다”처럼 번역하고 상세 원인은 진단 영역으로 옮긴다.

### P2 — 동일한 A/B 상태 저장 허용

- P01·P02 모두 배치를 바꾸지 않고 A안·B안을 저장할 수 있었다.
- 후보 조치: 배치 fingerprint가 같으면 차이가 없음을 알리고 저장 여부를 재확인한다.

## 결론

페르소나 검증의 핵심 반증은 CV 자체보다 **초기 가구 배치의 방 귀속 표시 누락**이다. 후속 코드 감사에서 스토어 경계의 무검증 삽입도 별도로 확인됐으므로 두 문제를 함께 첫 P1으로 올리는 것이 타당하다. 그다음은 추정 축척의 2D 검수 강제와 2D 원본 비교 유지다.

실제 사람 대상 M23 항목은 완료로 표시하지 않는다. 실제 사용자 확보 전에는 이 결과를 휴리스틱 사전 점검으로만 사용한다.
