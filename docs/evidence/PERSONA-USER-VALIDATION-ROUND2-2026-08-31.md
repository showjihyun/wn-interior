## 범위와 한계

- 기준점: `2cc7fd6`, 2026-08-31, Chromium, 1440×900
- 방식: 1차와 동일한 초보자 2명·중급자 1명의 행동 규칙과 입력을 유지하고, 서로 격리된 Playwright 브라우저 세션에서 `docs/USER-VALIDATION.md`의 핵심 과업을 다시 수행했다.

- 자동화 및 명령 지연이 섞인 실행 시간은 5분/20분 목표 판정에서 제외했다.

## 새로 확인된 반복 이슈

### P1 — 원본 검수 체크가 실제 보정 또는 근거 있는 “수정 불필요” 판정을 증명하지 못함

- P01과 P02 모두 네 체크박스를 선택해 3D 잠금을 해제했지만, 벽·방·문·창문·치수 중 실제 변경은 0건이었다.
- 현재 UI는 사용자가 무엇을 비교했는지, 어떤 치수를 확인했는지, 오류가 없어 수정하지 않았는지를 구분해 남기지 않는다.
- 단순히 수정을 강제하면 정상 결과를 일부러 훼손하게 되므로, 다음 구현은 대표 요소 1개를 선택해 원본과 확인하도록 하고 `수정 완료` 또는 `수정 불필요`를 명시적으로 기록하는 방향이 적절하다.
- 두 독립 초보자 세션에서 반복됐고 사용자 검증의 핵심 2D 과업을 무력화하므로 다음 P1으로 분류한다.

### 관찰 — 큰 제품의 방 내부 초기 배치가 거부됨

- P01에서 KIVIK 소파를 보이는 방에 배치하려 했으나 `방 안에만 배치할 수 있어요`로 거부됐다.
- 사용자는 더 작은 가구로 즉시 회복했고 경계 밖 삽입이나 데이터 손실은 없었다. 현재 증거만으로 제품 결함인지 실제 공간 부족인지 구분되지 않아 우선순위 이슈로 승격하지 않는다.

## 결론과 다음 우선순위

1차에서 발견한 여섯 회귀 항목은 모두 의도대로 수정됐다. 특히 P03의 부정확한 2방 결과는 더 이상 적용할 수 없고, P01·P02의 가구는 실제 방 귀속과 경계 검사를 통과했다.

다음 우선순위는 **2D 검수를 체크박스 통과가 아니라 근거가 남는 확인 단계로 바꾸는 것**이다. 대표 벽·문·치수 하나를 원본과 연결해 확인하고, `수정 완료`와 `수정 불필요`를 구분 저장하면 정상 결과를 훼손하지 않으면서도 형식적 체크만으로 3D에 진입하는 문제를 줄일 수 있다.

실제 사람 대상 M23 항목은 완료로 표시하지 않는다.
