## 새 관찰

### P2 후보 — SVG 문 선택이 포인터 정밀도에 의존함

- P01에서 접근성 트리의 문 그룹 중심 클릭은 SVG 배경에 가로막혔고, 화면에 보이는 문 선을 좌표로 클릭했을 때 선택됐다.
- 실제 포인터 사용자는 보이는 문을 클릭해 진행할 수 있었지만, 문 요소에는 키보드 초점과 접근 가능한 이름이 없어 키보드·보조기술 경로가 없다.
- 한 세션의 첫 관찰이며 핵심 과업 우회나 데이터 손실은 아니므로 P2 후보로 기록한다.
- 후보 조치: 벽·방·문 SVG 요소에 `tabIndex`, 역할·이름, Enter/Space 선택을 제공하고 실제 도형을 덮는 일관된 히트 영역을 둔다.

## 결론과 다음 우선순위

M30은 집중 회귀 범위에서 통과했고 2차의 반복 P1은 해소됐다. 다음 공식 우선순위는 여전히 M23 실제 사용자 3~5명 검증이다. 실제 사용자 모집 전 진행 가능한 개발 후보는 위 P2의 2D SVG 키보드 접근성·히트 영역 보강이지만, 한 번의 자동화 관찰만으로 P1로 승격하지 않는다.
