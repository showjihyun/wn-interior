## 2. 공식 환경 재현 시 발견한 문제

공식 설치 지침을 그대로 적용하면 현재 패키지 해석기에서 재현되지 않았다.

1. 공식 `numpy==1.26.4`와 `scipy==1.8.1`은 의존 범위가 충돌한다.
2. 공식 `make.sh`는 Ubuntu 이미지에 없는 `python` 별칭을 가정한다.
3. `models/ops/setup.py`는 Docker 빌드 단계에 GPU 장치가 없으면 CUDA 툴킷이 있어도
   컴파일을 거부한다.
4. 첫 추론에서 ResNet-50 97.8MB를 추가 다운로드한다.
5. 체크포인트 로드 시 KV-cache 관련 키가 `Unexpected Keys`로 보고된다. 공식 코드는
   `strict=False`로 계속 실행한다.

재현 Dockerfile은 PyTorch 2.3.1/CUDA 11.8과 모델 코드를 그대로 유지하면서 다음만 조정했다.

- OpenCV `4.10.0.84`, SciPy `1.11.4`
- `python3.10 setup.py` 직접 실행
- 빌드 시 `CUDA_HOME` 기준으로 sm_86 확장 컴파일
- ResNet-50 파일을 SHA-256으로 고정한 읽기 전용 캐시로 마운트

## 3. 공정한 비교 방법

- 표본: 기존 1,000건 중 개발 분할 `manifest index % 10 == 0`인 동일 100건
- 정답: 동일 CubiCasa SVG 방 폴리곤
- 좌표: Raster2Seq 레터박스 좌표를 원본 이미지 좌표로 역변환
- 방 매칭: 기존 평가와 동일한 128×128 셀 중심 래스터, IoU 0.5, 1:1 탐욕 매칭
- 형상 정규화: 형상을 바꾸지 않는 연속 중복점과 영면적 직선 스파이크만 제거
- 자기교차를 `buffer(0)` 등으로 임의 복구하지 않음
- 심각 중첩: 교집합이 작은 방 면적의 2%를 초과하는 경우

| 지표 | 결과 | 게이트 | 판정 |
|---|---:|---:|---|
| 무효·자기교차 폴리곤율 | **7.62%** | ≤1% | 실패 |
| 심각 중첩 영향 폴리곤율 | **10.66%** | ≤5% | 실패 |

| 원본 영역 밖 꼭짓점율 | 0.14% | 참고 | 낮음 |
| 제거한 연속 중복 꼭짓점 | 464개 | 기록 | 정규화됨 |
| 제거한 영면적 직선 꼭짓점 | 412개 | 기록 | 정규화됨 |
| 평균 순수 추론 | **1,921.35ms** | ≤2,000ms | 통과 |
| 최초 실행 포함 wall time | 396.952초/100건 | 기록 | 약 3.97초/건 |
| PyTorch 최대 CUDA 할당 | 295.9MiB | 기록 | 통과 |

Windows WDDM의 `nvidia-smi` 전체 GPU 최고값 11,227MiB에는 다른 프로세스가 포함됐다.
프로세스 내부 `torch.cuda.max_memory_reserved()`를 별도 측정한 결과는 324MiB였다. 따라서
RTX 3060 12GB에서 추론 가능하다는 결론은 실제 실행으로 확인됐다. CPU 전용 실행은 공식
커스텀 CUDA 연산 때문에 지원되지 않는다.

## 7. 최종 판단

**정확도만 보면 교체 가치가 충분하지만, 현재 출력 그대로는 3D 생성 기본 경로로 교체하면
안 된다.** 자기교차와 방 중첩은 바닥 메시·벽 정합·충돌 계산을 깨뜨릴 수 있다.

다음 연구 순서는 아래로 제한한다.

1. Raster2Seq를 기능 플래그 뒤의 방 후보 엔진으로 유지한다.
2. 기존 CubiCasa 벽 그래프에 방 경계를 스냅하고, 자기교차·중첩을 탐지해 실패 시 기존 방
   경로로 폴백한다.
3. 기하 복구 알고리즘은 개발셋에서만 조정한다.
4. 무효율 ≤1%, 심각 중첩 ≤5%를 통과한 뒤에만 홀드아웃 900건을 1회 실행한다.
5. 기존 문·창문 CNN 직접 채널은 유지한다.

코드와 체크포인트 페이지는 MIT로 표시되지만 학습 원천 CubiCasa5K는 CC BY-NC 4.0이다.
상업 적용 전 데이터 계보와 체크포인트 사용권을 별도 확인해야 한다.
