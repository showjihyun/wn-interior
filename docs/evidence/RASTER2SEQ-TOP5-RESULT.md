## 2. 평가 기준

- 데이터: CubiCasa5K에서 기존 1,000건 평가와 동일하게 고정한 dev 100건과 holdout 900건
- 학습: 추가 학습 없음. 공개 Raster2Seq CubiCasa5K 체크포인트를 그대로 사용
- 모델 고정:
  - Raster2Seq commit `a6c4e27a68d11d7a459f6e4a2601fd887227dd1a`
  - checkpoint SHA-256 `F7C0EF9379AA8CF11349DA8B2179214E0D495AF758383984A2361A1309AAB3B7`
- 매칭: 128×128 중심점 래스터, 독립 방 IoU, IoU 0.5 이상 매칭 수를 우선 최대화하는 이분 매칭
- 안전 선택:
  1. 연속 중복점과 공선 스파이크 제거
  2. 완전히 noding한 경계가 정확히 한 개의 구멍 없는 면을 만들 때만 자기교차 복구
  3. 앞선 방과 겹치는 영역을 순차적으로 제외하되 단일·구멍 없는 폴리곤이고 원래 면적의 35% 이상 남을 때만 허용
  4. 모호한 복구, 2% 초과 원본 좌표 이탈, 무효 폴리곤 또는 남은 중첩이 있으면 해당 사례 전체를 기존 방식으로 폴백
- 비율 표기: 사례별 평균인 macro 비율과 전체 폴리곤 기준 micro 비율을 함께 저장

이 평가는 방 폴리곤 기하 정확도다. 벽·문·창문·3D 메시 전체 품질을 하나의 수치로 오인하지 않는다.

원시 출력의 평균 F1은 기존보다 26.73%p 높지만 그대로 사용하면 무효·중첩 폴리곤이 많아 3D 바닥 메시 입력으로 안전하지 않다. 엄격 선택 후에도 기존보다 13.31%p 높지만, 절대 F1 기준 65%를 통과하지 못했다.

제품에는 여기에 벽 표면 지지율, 최소 0.2m², 방 개수 sanity gate가 추가된다. 이 추가 검사는 900건 평가에 포함되지 않았으므로 제품의 실제 Raster2Seq 채택률과 F1은 위 엄격 선택 결과보다 같거나 낮다. 따라서 60.83%는 운영 성능의 낙관적 상한으로 본다.

## 4. 성능과 GPU·CPU 판정

| 항목                   |                       측정값 |
| ---------------------- | ---------------------------: |
| GPU                    | NVIDIA GeForce RTX 3060 12GB |
| 900건 평균 순수 추론   |                1,558.56ms/건 |
| 900건 wall time        |                   1,482.84초 |
| PyTorch peak allocated |                     319.8MiB |
| PyTorch peak reserved  |                     452.0MiB |
| 프로세스 관찰 GPU peak |                     1,545MiB |

12GB VRAM에서는 충분히 실행된다. 다만 고정 Raster2Seq의 `MSDeformAttn` CPU 연산자는 실제 소스에서 구현되지 않아 Raster2Seq 자체를 CPU로 실행할 수 없다. GPU가 없거나 Raster2Seq가 실패하면 앱은 CPU 가능한 CubiCasa CNN 또는 기존 TypeScript CV 방 생성 경로로 자동 복귀한다. CPU에서 Raster2Seq가 실행된다고 표기하지 않는다.

## 5. 제품 안전 장치

- 기본값은 `legacy`; 자동 교체하지 않는다.
- `VITE_ENABLE_NONCOMMERCIAL_RESEARCH_MODE=true`가 없으면 Raster2Seq UI와 요청을 강제로 비활성화한다.
- `VITE_ROOM_POLYGON_ENGINE=raster2seq`는 연구 모드에서만 초기 선택에 사용한다.
- `safe: true`가 명시된 서버 응답만 검토한다. 누락은 fail-closed다.
- 새 이미지 선택 시 이전 이미지의 CNN/Raster2Seq 요청을 취소하고 generation을 검증한다.
- 프리뷰로 검증한 동일 `RawPlan`만 적용해 프리뷰와 실제 결과가 달라지지 않게 했다.
- 서버는 원본 이미지 픽셀 좌표와 원본 크기를 반환하고, 클라이언트가 실제 마스크 크기와 `mmPerPx`로 변환한다.
- 실측 가로 폭 보정은 mm 단위 스냅·최소 면적 검사 전에 적용한다.
- CubiCasa5K 학습 계보 체크포인트는 CC BY-NC 4.0 제한 때문에 비상업 연구 전용으로 취급한다.

## 6. ChatGPT·Gemini 비교 상태

하네스는 다음을 검증했다.

- 동일 dev 100건과 동일 manifest만 허용
- raw VLM 결과와 동일 repair+fallback 결과를 분리
- 모델·프롬프트·스키마·이미지·API revision fingerprint가 일치할 때만 캐시 재사용
- OpenAI와 Gemini 모두 저장 비활성화, 이미지 high resolution
- 실제 응답 모델과 API revision이 없으면 증거 채택 거부
- 논리 사례 수뿐 아니라 재시도 포함 물리 HTTP 호출도 공급자별 100회로 제한
- `-ApproveLiveRun`과 `-ConfirmFreshEnvironmentKeys`가 모두 없으면 라이브 실행 거부
- dry-run 네트워크 호출 0회, 오프라인 테스트 6건 통과

2026-08-27 [OpenAI 공식 모델 문서](https://developers.openai.com/api/docs/models)에서 `gpt-5.6-sol`은 이미지 입력과 Responses API를 지원하고, [Google 공식 Gemini 문서](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-pro-preview)에서 `gemini-3.1-pro-preview`도 이미지 입력을 지원하는 유효한 preview 모델임을 확인했다.

실제 비교를 실행하지 않은 이유:

1. 대화에 노출된 OpenAI 키는 폐기·재발급해야 하며 사용하지 않았다.
2. 새 Gemini 키가 없다.
3. 공급자당 최대 100회 유료 호출과 비용 승인이 필요하다.
4. 이 비교는 방 폴리곤 추출이며 완전한 2D→3D 결과 비교가 아니다.
