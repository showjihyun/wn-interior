Architecture

핵심 불변식레이어와 의존성런타임 조립상태·트랜잭션운영 경계비판적 평가
01

Invariants

뷰보다 데이터가 먼저입니다.

시스템의 중심은 화면 컴포넌트가 아니라 버전이 고정된 Project입니다. 좌표와 치수, 배치, 사용자 제품, 도면 검토 근거가 이 경계 안에서 이동합니다.

Project v1 ├─ plan: FloorPlan { unit: "mm", walls, openings, rooms } ├─ placements: Placement[] { productId, pos, rotY, supportPlacementId? } ├─ customProducts: Product[] ├─ floorPlanReview?: source image + scale + evidence └─ id / name / origin / createdAt / updatedAt
경계 불변식 실패 방지
단위 저장되는 모든 공간·제품 길이는 mm 픽셀과 월드 단위의 암묵적 혼용을 막음
좌표 2D의 (x, y)는 3D의 (x, z), 높이는 3D y 두 뷰의 배치 드리프트를 막음
렌더링 SVG와 R3F는 같은 Zustand 프로젝트 상태를 구독 별도 저장 모델로 갈라지는 것을 막음
가져오기 Project v1·mm·필수 배열을 검증한 뒤 로드 형식이 다른 JSON의 조용한 적용을 막음
설치 부착 관계는 supportPlacementId와 capability 계약으로 표현 수전을 임의 가구 위에 얹는 것을 막음
02

Dependency direction

프레임워크는 가장 바깥에 둡니다.

도메인은 React나 브라우저 API를 모릅니다. 애플리케이션은 포트를 정의하고, 인프라는 그 포트를 구현하며, 프레젠테이션은 조립된 런타임만 소비합니다.

Presentation

React UI, Zustand 바인딩, SVG 편집기, R3F 씬, 텍스처·표면 registry

src/presentation
Infrastructure

IndexedDB/sessionStorage, HTTP AI·CV, 다운로드, 정적 상품·재질, catalog file bridge

src/infrastructure
Application

프로젝트 생명주기, 편집·히스토리·자동저장, 분석·견적, protocol import, 포트

src/application
Domain

mm 모델, 기하, 충돌·배치, 설치 의존성, 보행·점프, 도면 해석 규칙

src/domain
dependency direction → domain

정적 정책 테스트와 DOM 라이브러리 없는 별도 TypeScript 컴파일이 이 경계를 검사합니다. compositionRoot.ts는 구체 구현을 연결할 수 있는 유일한 조립 지점입니다.

State & transactions

편집은 즉시 미리 보고, 확정할 때 한 번 기록합니다.

Interaction state

  • 선택·이동 중·pending placement
  • 카메라·워크스루·모달 상태
  • 부착 후보와 미리보기
→

Project state

  • plan·placements·customProducts
  • 확정된 support chain
  • Undo/Redo와 autosave 대상

객체 드래그 중에는 미리보기 좌표를 보여주고 확정 시 편집 명령으로 커밋합니다. 부모 오브젝트 이동은 부착된 자식의 상대 위치를 함께 전파합니다. 추가·삭제·부착·분리 후 견적은 현재 placements에서 다시 계산됩니다.

Product.installation→capability check→support candidate→Placement.supportPlacementId→move propagation
05

Operational boundaries

웹 앱, 연구 서비스와 생성 자산의 수명을 분리합니다.

경계 Production 기본값 대체·복구 경로
프로젝트 저장 URL workspace별 IndexedDB + session mirror IndexedDB 실패 시 sessionStorage; 장기 보관은 JSON export
평면도 CV 브라우저 classical CV 로컬 segmentation/CNN은 개발 또는 명시적 연구 모드
AI 분석 OpenAI-compatible gateway, 사용자 설정 인증·쿼터·rate limit·응답 오류를 유형화해 표시
3D 생성 메시 승인 자산 없으면 공식 이미지 투영·파라메트릭 형상 TripoSR worker는 오프라인; 해시·권리·사람 검수 후에만 publish
웹 배포 Vite 정적 빌드 → Vercel dist workers/는 Vercel 빌드 경계 밖

저장 ≠ 동기화

IndexedDB는 같은 브라우저에서 탭을 닫아도 프로젝트를 유지하지만 계정 기반 백업이나 기기 간 동기화를 제공하지 않습니다. 이 차이를 UI와 문서에서 계속 명시해야 합니다.

06

Critical assessment

구조는 건강하지만 운영 완결성은 아직 로컬 중심입니다.

STRENGTH

도메인 경계가 실제 도구로 보호됨

폴더 이름만 클린 아키텍처인 것이 아니라 역참조 정책 테스트와 DOM-free compile이 있어 회귀를 빠르게 감지합니다.

RISK 01

Project v1 validation 깊이가 얕음

import는 최상위 필드와 배열 존재를 확인하지만 모든 중첩 좌표·ID·참조 무결성을 완전 검증하지는 않습니다. 외부 문서 호환성이 커질수록 schema 기반 deep validation이 필요합니다.

RISK 02

프레젠테이션 registry가 런타임 객체로 함께 조립됨

scene surface·texture status는 UI 외부 효과이므로 현재 위치가 타당하지만, 기능이 커지면 프레임 수명과 프로젝트 수명의 혼동을 피하도록 dispose 계약이 필요합니다.
